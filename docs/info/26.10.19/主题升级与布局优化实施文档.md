# BioReport HTML 科研报告 UI/UX 主题升级与布局优化实施文档

**项目：** BioReport RNA-seq Scientific Report  
**改造类型：** Quarto HTML 报告前端样式与交互体验升级  
**实施原则：** 保留现有报告生成机制、分析结果、数据结构和交互能力，优先通过 Quarto 配置、CSS/SCSS 与现有组件配置完成升级。

---

## 一、项目目标

### 1.1 当前问题

基于现有报告页面，识别出以下需要解决的问题。

| 模块 | 当前问题 | 改造目标 |
|---|---|---|
| 正文布局 | 内容区域偏窄，左右留白过多 | 扩展正文和图表可用宽度 |
| 导航 | 顶部导航与左侧目录占用空间较多 | 优化宽屏布局、层级和响应式行为 |
| 图表 | PCA 等图表显示局促，部分区域留白不协调 | 提供统一的图表容器与自适应布局 |
| 数据表格 | 列名被截断，宽表格无法完整查看 | 支持横向滚动、完整列名和合理列宽 |
| 表格样式 | 行高、间距、表头和分页工具栏不够协调 | 建立统一的数据表格视觉规范 |
| 指标卡片 | 卡片、边框、文字和间距需要统一 | 建立可复用的统计卡片样式 |
| 章节排版 | 标题、正文、图表和说明之间的层级不够统一 | 建立完整的排版体系 |
| 移动端 | 宽图表和宽表格可能影响阅读 | 实现响应式布局 |
| 报告交付 | 样式调整不能破坏独立 HTML 的交付能力 | 保留现有资源打包与离线使用机制 |

### 1.2 总体目标

将 BioReport 从默认样式下的 Quarto 分析报告，升级为具有统一品牌视觉的专业科研报告系统。

本次改造重点是：

1. **Layout System：** 建立适合科研分析的宽屏页面布局。
2. **Table System：** 建立适合 RNA-seq 表达矩阵、差异表达结果和富集分析结果的数据表格体系。
3. **Visualization System：** 统一 Plotly 图表、静态图和图注的展示方式。
4. **Design System：** 统一字体、颜色、标题、卡片、边框、间距和交互状态。
5. **Responsive System：** 适配桌面、平板和移动设备。
6. **Delivery Compatibility：** 保留现有 Quarto 渲染、报告数据、分析逻辑和交付方式。

### 1.3 本次不做的事情

- 不重写 RNA-seq 分析流程。
- 不修改差异表达、PCA、富集分析等统计方法。
- 不改变表达矩阵的底层数值和精度。
- 不直接替换当前表格库或图表库。
- 不重建独立的 Vue、React 前端应用。
- 不随意更换顶部导航、Logo、页面章节名称和现有品牌元素。
- 不默认引入需要联网加载的第三方 CSS、字体或 JavaScript。
- 不以牺牲图表交互、表格排序、分页、搜索或数据导出为代价换取视觉效果。

## 二、总体设计规范

### 2.1 视觉方向

采用“专业科研报告 + 现代数据分析产品”的视觉方向。

核心特征：

- 白色为主背景，浅灰蓝作为辅助背景。
- 深海军蓝作为标题与正文的主要颜色。
- 科研蓝作为链接、激活状态和重点交互的强调色。
- 卡片使用轻量边框和适度圆角。
- 避免过多阴影、渐变、大面积彩色背景和装饰性元素。
- 统计结果、图表、表格应当成为页面的视觉重点。

### 2.2 色彩变量

建议先建立以下主题变量，再由全部组件引用。

| 变量 | 色值 | 用途 |
|---|---|---|
| `--br-primary` | `#2563EB` | 主强调色、链接、导航激活状态 |
| `--br-primary-dark` | `#203A5F` | 页面标题、重要文本 |
| `--br-text` | `#334155` | 正文 |
| `--br-muted` | `#64748B` | 辅助说明、次级文本 |
| `--br-border` | `#E2E8F0` | 卡片、表格和分隔线 |
| `--br-surface` | `#FFFFFF` | 主背景 |
| `--br-surface-soft` | `#F8FAFC` | 表格交替行、辅助区域 |
| `--br-surface-hover` | `#EFF6FF` | 表格行悬停和轻量交互状态 |
| `--br-success` | `#15803D` | 成功或合格状态 |
| `--br-warning` | `#B45309` | 警告状态 |
| `--br-danger` | `#B91C1C` | 错误或异常状态 |

状态颜色不能只通过颜色传达，还应结合文本、图标或明确标签。

### 2.3 字体规范

- 中文优先使用系统可用的现代无衬线字体。
- 英文与数字采用清晰的系统无衬线字体。
- 基因 ID 可以使用等宽字体，以提高字符辨识度。
- 正文建议为 `15–16px`。
- 表格正文建议为 `13–14px`。
- 表格标题建议为 `12–13px`，字重适度提高。
- 辅助说明建议为 `12–14px`。
- 不建议为了容纳宽表格而将全部文字缩小到难以阅读的程度。

## 三、页面布局系统改造

### 3.1 正文宽度

当前报告正文主要集中在屏幕中央。建议将布局划分为三个层级：

| 内容类型 | 建议最大宽度 | 设计要求 |
|---|---:|---|
| 普通正文 | 1100–1200px | 提升可用宽度，同时保留可读性 |
| 统计卡片区域 | 1100–1200px | 统一卡片列宽与间距 |
| 图表与数据表格 | 1200–1400px | 在宽屏下利用额外空间 |
| 移动端内容 | 100% | 根据视口自动收缩 |

以上数值是初始设计目标，不是强制固定值。最终宽度需要结合 Quarto 的实际页面网格、导航目录、浏览器视口和现有 CSS 进行验证。

### 3.2 Quarto 配置调整

首先检查现有 `_quarto.yml`、`.qmd` 文件的 YAML 配置，确认主题、目录、导航和 CSS 的来源。

如果当前报告使用 Quarto 标准 HTML 页面布局，可以在保留现有设置的基础上，参考以下配置：

```yaml
format:
  html:
    page-layout: full
    grid:
      body-width: 1150px
      margin-width: 220px
      gutter-width: 1.5rem
    css:
      - styles/report.css
```

注意：

1. 这是配置示例，不是要求直接覆盖现有 YAML。
2. 如果当前使用 `theme`、`toc`、`toc-location`、`embed-resources` 或其他 HTML 选项，必须保留并合并。
3. 如果当前已有自定义布局，不要强行切换到 `page-layout: full`，应先确认切换不会破坏页面结构。
4. 如果使用主题的 `max-width` 设置限制了内容区域，需要同时检查主题宽度上限。
5. Quarto 的 `body-width`、`margin-width` 是页面网格的基础宽度参数，并不等于简单设置某个 DOM 元素的固定宽度。

官方文档：

- [Quarto Page Layout](https://quarto.org/docs/output-formats/page-layout.html)
- [Quarto HTML Theming](https://quarto.org/docs/output-formats/html-themes.html)

### 3.3 导航栏

保留现有顶部导航结构和 BioReport 品牌标识，主要优化：

- 统一导航栏高度和垂直对齐。
- 保持 Logo、品牌名称和副标题的比例。
- 增强当前激活章节的识别度。
- 统一菜单项的间距、字体和悬停状态。
- 检查顶部导航是否遮挡章节标题或锚点定位内容。
- 在小屏幕上使用合理的折叠菜单，而不是让所有导航项挤在一行。
- 避免同时出现过宽的顶部导航、左侧目录和过窄的正文区域。

### 3.4 左侧目录

当前左侧目录结构可以保留，但需要明确它的功能是章节导航，而不是额外的内容栏。

优化要求：

- 目录宽度适中，不要抢占正文空间。
- 章节层级清晰，当前章节具有明显但克制的激活状态。
- 目录文字过长时合理换行。
- 页面滚动时，目录状态与实际章节同步。
- 小屏幕下按 Quarto 的原生响应式行为折叠或隐藏。
- 不要同时用多套机制重复生成章节目录。

### 3.5 章节排版

建议统一使用以下排版层级：

- H1：页面主标题。
- H2：主要报告章节。
- H3：分析模块标题。
- H4：模块内部的小节标题。
- 正文：统一字体、行高和段落间距。
- 图注、表注：采用次级文本样式。

章节标题下的分隔线可以保留，但应统一粗细、颜色和间距。避免每一个小标题下面都添加明显的长横线，导致页面视觉过重。

## 四、表格系统改造

### 4.1 第一优先级：解决宽表格截断

现有表达矩阵表格已经显示出列名不完整、右侧内容不可见的问题。该问题必须优先解决。

具体要求：

1. 表格容器必须限制在页面可用宽度内。
2. 当列总宽度超过容器宽度时，允许横向滚动。
3. 不允许通过 `overflow: hidden` 静默裁切表格内容。
4. 保证横向滚动时，用户仍然可以清楚地识别当前查看的样本列。
5. 长列名应采用换行、合理最小列宽或悬浮提示，而不是无提示地截断。
6. 页面宽度变化时，表格不能覆盖导航、正文或相邻组件。

如果现有表格库支持固定首列，可以将 `GENE_ID` 作为固定列的候选。但固定首列需要在实际渲染器中验证，不能仅通过添加 `position: sticky` 就假定已经实现可靠的固定列行为。

### 4.2 表头样式

建议采用浅蓝灰色或浅灰色表头，搭配深色文字。

具体要求：

- 表头与正文有清晰的视觉区分。
- 字体加粗但不使用过重的字重。
- 表头底部使用细边框。
- 列名允许在必要时合理换行。
- 排序图标使用统一的颜色和尺寸。
- 排序激活状态需要清晰可见。
- 如果当前表格库支持固定表头，应先验证其原生机制，再决定是否启用。

### 4.3 行与单元格

建议使用轻量级斑马纹和悬停状态：

- 奇数行使用白色背景。
- 偶数行使用非常浅的灰蓝背景。
- 鼠标悬停时采用浅蓝色背景。
- 避免每个单元格都添加厚重的边框。
- 统一行高、单元格内边距和文本对齐。
- 基因 ID 默认左对齐。
- 数值列默认右对齐。
- 分类、状态或文本列根据实际语义设置对齐方式。

表格应优先保证可读性，不应为了视觉装饰加入不必要的渐变、阴影和强烈颜色。

### 4.4 数值格式

不同类型的数据必须采用不同的展示策略。

| 数据类型 | 展示策略 |
|---|---|
| 原始 read counts | 保留整数语义，不强行添加无意义的小数 |
| 标准化表达量 | 根据数值范围采用适当的小数位数 |
| Fold Change | 保留足够的解释精度 |
| FDR / adjusted p-value | 使用适当有效数字，极小值可考虑科学计数法 |
| 百分比 | 统一百分比位数和单位 |
| 基因 ID、样本 ID | 保留原始标识符，不做数值格式化 |

必须区分“显示精度”和“底层数据精度”。

样式层面的格式化不能改变统计结果，也不能影响排序、搜索、复制和导出的数据。如果现有表格库使用格式化后的文本进行排序，应进一步检查是否可以基于原始数值排序。

### 4.5 分页与工具栏

统一表格工具栏布局：

- 左侧显示当前展示范围和总记录数。
- 右侧提供搜索、每页行数和导出等操作。
- 分页区域与表格主体之间保持合理距离。
- 当前页码状态明确。
- 按钮、输入框和下拉框高度一致。
- 移动端允许工具栏换行。
- 不应出现分页器脱离表格、表头上方存在异常空白等问题。

需要先调查现有表格是否使用 ITables、DataTables、Quarto 分页表格或其他实现，再确定具体配置。

如果使用 ITables/DataTables，应优先沿用当前排序、分页和搜索机制。若使用 Quarto 的原生分页表格，则应先确认实际渲染路径。不要仅为样式统一而替换整套表格库。

### 4.6 表格容器与 CSS 结构

建议为不同类型的表格建立统一的样式入口，例如：

- `br-table`
- `br-table--expression`
- `br-table--results`
- `br-table__toolbar`
- `br-table__pagination`

这些类名是设计建议，实际使用前应检查现有 HTML 输出，确认可以通过报告模板、渲染器或受控包装容器添加它们。

不要未经调查就把 `.dataTables_wrapper`、`.dt-container`、`.itables` 等选择器当作当前项目的既定结构。应以实际 DOM 为准，针对现有渲染器编写兼容规则。

## 五、图表与可视化系统

### 5.1 统一图表容器

为 PCA、表达量分布、差异分析、富集分析和其他科研图表建立统一的展示规范。

建议包括：

- 图表标题。
- 图表主体。
- 必要的图注和解释。
- 统一的上下间距。
- 合理的图例位置。
- 与报告正文一致的字体和颜色。

不建议给每张图都添加厚重的卡片边框。如果图表本身具有明显的坐标轴、图例和标题，容器只需提供足够的留白即可。

### 5.2 PCA 图布局

针对当前 PCA 图，建议：

1. 桌面宽屏下，允许多个 PCA 视图并排展示。
2. 每张图具有足够的可视区域，避免标签重叠。
3. 图例与绘图区保持合理距离。
4. 图表容器宽度自适应，不能只扩大外部 CSS 宽度却不调整图表内部布局。
5. 小屏幕下自动改为单列。
6. 保留原始交互能力，包括悬停信息、缩放和导出（如果当前已支持）。

对于 Plotly，应优先使用图表本身的响应式布局配置和现有的容器适配机制，而不是单纯依赖 CSS 强制改变宽度。

### 5.3 图表颜色与可读性

- 统一报告内的字体、标题和辅助文本。
- 同一实验分组在不同图表中尽量保持一致的颜色映射。
- 不同分组应具有足够的视觉区分度。
- 不应只依靠颜色表达显著性或质控状态。
- 图注必须说明图表展示的指标或分析目的。

### 5.4 图表布局与 Quarto

如果当前 QMD 文件中存在多个连续的图表，可以在确认当前布局机制后，考虑使用 Quarto 原生的布局能力组织双列或多列图表。

参考：

- [Quarto Component Layout](https://quarto.org/docs/interactive/layout)
- [Quarto Gallery](https://quarto.org/docs/gallery/)

本次优先优化现有图表布局，不要求重写所有图表生成代码。

## 六、统计卡片与分析说明

### 6.1 统计卡片

项目概述页中的样本数、数据量、Q30 等指标可以保留现有信息结构，但需要统一样式。

卡片规范：

- 统一边框颜色、圆角和内边距。
- 统一标题、主要数值和辅助说明的字体层级。
- 数字应成为视觉重点。
- 单位与数字之间保持合理间距。
- 卡片高度尽量协调，但不能通过固定高度导致内容被裁切。
- 桌面端可使用三列布局。
- 小屏幕自动切换为两列或单列。

不要让每个卡片都使用不同的图标颜色、边框颜色和装饰方式。

### 6.2 分析声明与提示框

现有分析声明可以保留轻量化设计，统一为提示组件。

建议分为：

- `info`：普通说明。
- `success`：通过质控或满足条件。
- `warning`：需要关注的问题。
- `error`：分析失败或严重异常。

每类提示都应使用适当的文字标签或图标。不能仅依靠边框颜色区分状态。

### 6.3 报告各章节的统一性

以下页面应使用同一套设计规范：

1. 项目概述。
2. 样本信息。
3. 分析概述。
4. 质量控制。
5. 分析结果。
6. 溯源信息。
7. 关于页面（如果属于同一报告模板）。

允许各章节有不同的组件组合，但不允许各自维护完全独立的颜色、字号和间距体系。

## 七、CSS/SCSS 工程组织

### 7.1 推荐文件结构

在现有项目结构基础上，优先建立或复用以下样式文件：

```text
styles/
├── report.css
├── report-theme.scss
└── components/
    ├── tables.css
    ├── charts.css
    └── cards.css
```

该目录结构仅为建议。如果现有项目已有集中管理的样式目录，应优先扩展现有结构，而不是重复建立同类文件。

职责划分：

- `report-theme.scss`：主题变量、Bootstrap/Bootswatch 定制。
- `report.css`：布局、正文、导航和报告级别的样式。
- `tables.css`：表格、工具栏、分页和宽表格行为。
- `charts.css`：图表容器和图注。
- `cards.css`：统计卡片、提示框等组件。

如果当前项目较小，可以先将样式集中在一个 CSS 文件中，待组件数量增加后再拆分。不要为了文件结构漂亮而过度工程化。

### 7.2 主题配置

如果当前报告使用 Quarto 的 Bootstrap/Bootswatch 主题，可以在保留现有基础主题的前提下添加自定义 SCSS。

例如：

```yaml
format:
  html:
    theme:
      - cosmo
      - styles/report-theme.scss
    css:
      - styles/report.css
```

这里的 `cosmo` 只是示例。如果项目当前使用其他主题，应保留实际主题名称。

SCSS 文件可以包含：

```scss
/*-- scss:defaults --*/

// 根据现有主题设置统一变量。
// 不要在没有确认当前主题的情况下批量覆盖所有 Bootstrap 变量。

/*-- scss:rules --*/

// 放置需要覆盖的组件样式。
// 优先使用清晰、范围明确的选择器。
```

如果现有报告并未使用 Bootstrap 主题或已采用自定义主题，应先调查再决定是否引入该配置。

### 7.3 CSS 实现原则

1. 颜色、字体、圆角和间距优先使用统一变量。
2. 选择器应尽可能具有明确的作用范围。
3. 避免大量使用 `!important`。
4. 不要使用全局规则强行覆盖所有 `table`、`button`、`img` 或 `div`。
5. 不要修改 Quarto 内部布局结构，除非确实有必要且经过验证。
6. 不能通过隐藏元素掩盖布局错误。
7. 所有宽度、间距和字号都应在不同视口下验证。
8. 样式应能在每次重新生成 HTML 后稳定生效，而不是只对当前某一个已生成的 HTML 文件有效。

## 八、独立 HTML 与性能兼容性

BioReport 的样式升级必须与实际报告交付方式兼容。

### 8.1 资源打包

首先调查当前 HTML 的资源引用方式：

- CSS 是外部引用还是嵌入？
- Plotly JavaScript 是如何加载的？
- 图表数据是否嵌入 HTML？
- 是否使用 `embed-resources: true`？
- 是否需要将报告拷贝到另一台机器后直接打开？
- 是否存在依赖 CDN 的样式、脚本或字体？

如果当前交付方式要求单文件 HTML，应保留现有的资源打包机制。Quarto 的 `embed-resources` 可以将适用的依赖资源嵌入 HTML，但必须结合当前资源结构和报告体积进行测试。

官方文档：[Quarto HTML Basics](https://quarto.org/docs/output-formats/html-basics.html)。

### 8.2 性能要求

本次改造不应造成明显的性能退化。

重点检查：

- HTML 文件大小变化。
- 页面首次打开时间。
- 图表初始化时间。
- 表格分页与搜索的响应速度。
- 大型表达矩阵的滚动体验。
- 浏览器控制台错误。
- 是否重复加载 CSS 或 JavaScript。
- 是否引入不必要的第三方依赖。

不建议为了视觉美化而引入完整的前端框架、动画库或多套 UI 组件库。
